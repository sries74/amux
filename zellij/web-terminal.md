# Zellij Web Terminal — Native Approach

Zellij has a **built-in web server** and a **built-in `share` plugin** (written in zellij-tile/WASM) that manages it. No ttyd needed.

---

## How It Works

```
zellij web --start          # starts Axum HTTP server (default :8082)
  └── serves xterm.js frontend
  └── /ws/terminal  (PTY stream)
  └── /ws/control   (resize, config, session switching)
  └── /command/login (token auth)

share plugin (WASM)         # manages the web server from inside zellij
  └── start/stop web server
  └── generate login tokens
  └── toggle session sharing
```

The browser gets an **identical terminal experience** — same ANSI rendering, same keybindings, same scrollback — because it's the same PTY stream, just over WebSocket to xterm.js instead of a local tty.

---

## Start the Web Server

```bash
# Start (daemonized by default)
zellij web --start

# With custom port/IP
zellij web --start --port 8082 --ip 0.0.0.0

# With TLS
zellij web --start --cert /path/to/cert.pem --key /path/to/key.pem

# Check status
zellij web --status

# Stop
zellij web --stop
```

Or configure in `config.kdl`:
```kdl
web_server_ip "127.0.0.1"
web_server_port 8082
// web_server_cert "/path/to/cert.pem"
// web_server_key  "/path/to/key.pem"
```

## Enable the Share Plugin

Open the share plugin inside a running zellij session:

```bash
# From the zellij CLI
zellij plugin -- zellij:share

# Or add to your layout
layout {
    tab name="agents" {
        pane split_direction="vertical" {
            pane command="claude"
            pane {
                plugin location="zellij:share"
            }
        }
    }
}
```

Inside the plugin:
- **Enter** — start web server
- **Space** — toggle session sharing on/off
- **t** — generate a login token (required for browser access)
- **Ctrl-c** — stop web server

---

## Connect from the Browser

1. `http://localhost:8082` (or your IP/port)
2. Enter the token generated by the share plugin
3. Full terminal — you're in the zellij session

Tokens can be **read-only** (viewer) or **read-write** (full control). Revoke them any time from the share plugin.

## For the Multi-LLM Agent OS

The share plugin itself is the proof that **zellij-tile WASM is the right layer** for agent orchestration. Your orchestrator plugin can:

```rust
use zellij_tile::prelude::*;

// Start the web server programmatically
start_web_server();

// Share the session (make it accessible to browser clients)
share_current_session();

// Generate a token for a specific agent's web client
let token = generate_web_login_token(Some("agent-1".into()), false)?;

// Open a Claude pane
open_command_pane(CommandToRun {
    path: "claude".into(),
    args: vec![],
    cwd: None,
}, BTreeMap::new());

// Subscribe to web server + session events
subscribe(&[
    EventType::WebServerStatus,
    EventType::SessionUpdate,
    EventType::PaneUpdate,
]);
```

The browser connects to `/ws/terminal/{session}` — one URL per agent session, all served by the same Zellij web server.

---

## Session URLs

```
http://localhost:8082/              → current session
http://localhost:8082/project-1     → named session "project-1"
http://localhost:8082/agent-2       → named session "agent-2"
```

Multiple browser tabs can connect to different agent sessions simultaneously through a single web server instance.
